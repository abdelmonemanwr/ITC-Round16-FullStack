Stack vs Heap

Memory Management in C#

Stack Memory

  • Fast allocation
  • Fixed size (~1MB)
  • LIFO (Last In, First Out)
  • Auto cleanup when method ends

Stores: Value types, references (pointers)

Heap Memory

  • Slower allocation
  • Large size (GBs)
  • Random access
  • Garbage Collector cleans

Stores: Objects, arrays, strings

Data Location Example
Value Types (int, bool, struct) Stack int x = 10;
Reference (the pointer) Stack arr variable
Object Data Heap new int[] {1,2,3}

Value types store the actual data directly. When assigned, a copy of the value is created.

Reference types store a pointer to data on the heap. When assigned, only the reference is copied!

Type Casting & Conversion

Type Conversion is the process of converting a value from one data type to another. In C#, conversions can be done automatically (implicit) or manually (explicit).

Why do we need Type Conversion?

APIs expect specific types

Some methods need double, others need int — so we convert to match what they expect.

User input is always text

Console.ReadLine() returns a string, but math needs numbers → we convert.

To avoid bugs & be clear

Casting shows "I know what I'm doing"

Two Main Types

✓ Implicit (Automatic)

Done automatically by the compiler when it's safe (no data loss).

Caution: Explicit (Manual)

Requires manual casting. May cause data loss or exceptions.

Widening (Safe): Small → Large   |   Narrowing (Risky): Large → Small

Convert Class

The Convert class converts between base data types (string, int, double, bool, etc.). Commonly used when the source is an object.

Common Methods

ToInt32

string/object → int

ToDouble

string/object → double

ToBoolean

string/int → bool

ToString

any → string

Examples

int x = Convert.ToInt32("123");      // x = 123
double d = Convert.ToDouble("12.5");   // d = 12.5
bool b = Convert.ToBoolean(1);        // b = true
string s = Convert.ToString(99);      // s = "99"

Cast vs Convert

Cast (won't work)

string s = "123";
int x = (int)s; // × Error!

Convert (works)

string s = "123";
int x = Convert.ToInt32(s); // ✓ 123
Caution: Throws exception if conversion fails (FormatException, OverflowException). Use TryParse for untrusted user input!

Parse()

Throws exception if fails

Cleaner one-liner

Returns false if fails

Boxing & Unboxing

Boxing converts a value type (e.g., int) into an object by storing it on the heap. Unboxing extracts the value type back from the object.

Stack: Boxing

Value → Object

Heap allocation

Implicit (automatic)

Heap: Unboxing

Object → Value

Extracts from heap

Explicit (cast required)

Example

int x = 10;
object obj = x;       // Stack: Boxing (implicit)
int y = (int)obj;     // Heap: Unboxing (explicit cast)

Common Pitfall

object o = 10;           // boxed as int
long v = (long)o;       // × InvalidCastException!
long v = (long)(int)o;  // ✓ Unbox first, then convert

Caution: Must unbox to the exact original type first!

Boxing impacts performance due to heap allocation + GC pressure. Prefer generics (e.g., List<int>) to avoid boxing.

Nullable Value Types

Nullable value types allow a value type to store null. Nullable<T> represents any struct type that represents all values of its underlying value type T and an additional null value.

Point: Introduced in C# 2.0 (2005)

Definition: Microsoft Docs

Example

int age = 10;               // Non-nullable Integer
int? age = null;            // Nullable integer
Nullable<int> age = null;  // Nullable integer

Key Properties

.HasValue

Indicates whether an instance of a nullable value type has a value of its underlying type.

age.HasValue

.Value

Gets the value of an underlying type if HasValue is true. If HasValue is false, throws InvalidOperationException.

age.Value

Usage

int? score = null;
if (score.HasValue)
    Console.WriteLine(score.Value);
int safeScore = score ?? 0;  // safeScore = 0
Caution: Accessing .Value when null throws InvalidOperationException! Always use ?? or check .HasValue first.

Null-Conditional (Null-Propagation) Operator

The null-conditional operator (?. and ?[]) safely accesses members and elements only if the target is not null. If it is null, the whole expression evaluates to null instead of throwing an exception.

Point: Introduced in C# 6.0 (2015)

Without ?. ×

Manual null check required

if (user != null)
{
    Console.WriteLine(user.Name);
}

With ?. ✓

Clean & safe one-liner

Console.WriteLine(user?.Name);
// Returns null if user is null

Two Operators

?. (Member Access)

Access properties/methods safely

user?.Name

?[] (Index Access)

Access array/list elements safely

names?[0]

Note: Tip: ?. returns null — combine with ?? for a fallback value: user?.Name ?? "Guest"

Null-Coalescing Operators

Null-coalescing operators help you provide a fallback when a value is null. One of the most common tools with nullable types.

Point: ?? in C# 2.0 (2005) | ??= in C# 8.0 (2019)

?? (Null-Coalescing)

Returns right side if left is null

name ?? "Guest"

??= (Assignment)

Assigns right only if left is null

name ??= "Admin"

How ?? works:

result

"Guest"

=

name

null

??

fallback

"Guest"

Example

string? name = null;
string result = name ?? "Guest";  // result = "Guest"
name ??= "Admin";                 // name = "Admin" (was null)

Null-Conditional with Null-Coalescing

Combine ?. with ?? to safely access members and still return a default value if anything is null.

Note: Use them together: ?. prevents exceptions, ?? gives a default value

Example

string userName = user?.Name ?? "Guest";

What happens?

  • If user is null → result is "Guest"
  • If user.Name is null → result is "Guest"
  • If user.Name has a value → that value is used

More common patterns

// Numeric default
int itemCount = cart?.Items?.Count ?? 0;
// Nested safe navigation + fallback
string city = order?.Customer?.Address?.City ?? "Unknown";

This combo is a production standard for null-safety + readable defaults.

Null-Forgiving Operator (!)

The null-forgiving operator (!) tells the compiler: "I know this value is not null." It suppresses nullable warnings.

Point: Introduced in C# 8.0 (2019)

Caution: Compile-time Only

Suppresses compiler warnings

Works with Nullable Reference Types

× No Runtime Protection

Does NOT add null checks

Still throws NullReferenceException

Example

string? name = GetName();
// Compiler warning without !
Console.WriteLine(name!.Length);  // "Trust me, it's not null"

✓ Good Use Cases

• After validation

• Framework guarantees non-null

× Avoid When

• Unsure if value can be null

• Hiding a design problem

• Safer solution exists (?., ??)

Caution: Use ! as a last resort when you have a strong guarantee. Prefer ?., ??, or guard clauses whenever possible.
