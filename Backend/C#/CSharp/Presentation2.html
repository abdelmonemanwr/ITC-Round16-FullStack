Strings in C#

string is a reference type in C# used to represent text. It is immutable, meaning its contents cannot be changed after creation.

■ Immutable

□ Reference Type

Allocated on the heap

String Interning

String Interning is a memory optimization where the CLR maintains a pool of unique string literals. When you create identical string literals, they share the same memory location.

How it works

Without Interning

s1
→
0x001: "Hello"
s2
→
0x002: "Hello"

2 copies = wasted memory

With Interning

s1
→
0x001: "Hello"
s2
↗

Same reference = memory saved!

Code Example

string s1 = "Hello";
string s2 = "Hello";

Console.WriteLine(s1 == s2);                     // True (same content)
Console.WriteLine(object.ReferenceEquals(s1, s2)); // True (same object!)

Note: Interning only applies to string literals (compile-time). Runtime strings (e.g., from user input) are not automatically interned.

StringBuilder in C#

StringBuilder is a mutable class used for efficient string construction when you need many changes (append/insert/remove).

↻ Mutable

Edits modify the same object

□ Internal Buffer

Growing buffer, reusable memory

↯ Efficient

No new strings per operation

Common Methods

Append() AppendLine() Insert() Remove() Replace() ToString()

◆ Tip: If you know the approximate size, set capacity to reduce reallocations: new StringBuilder(1000)

String vs StringBuilder

✎ string

■ Immutable - creates new object each change

▣ Best for stable/read-only text

⚙ StringBuilder

↺ Best for many edits (loops, building text)

➜ Fast for frequent modifications

When to Use?

Use string: Few changes, reading, comparing, dictionary keys

Use StringBuilder: Loops, building HTML/JSON, logging, reports

◆ Rule of Thumb: If you're concatenating in a loop or making 3+ modifications, use StringBuilder!

String Formatting in C#

String formatting is how you build readable text output by inserting values into a string. C# supports multiple styles: concatenation, interpolation, composite formatting, and formatting helpers.

Common Approaches

  • + concatenation (simple, but not ideal for many parts)
  • $"..." interpolation (most readable)
  • string.Format (older, still useful)
  • Console.WriteLine with placeholders

Recommended for teaching & production: String Interpolation ($"...")

↧ Click to reveal

Concatenation vs Interpolation

Concatenation Not Recommended

string name = "Ahmed";
int age = 25;

string msg = "Name: " + name + ", Age: " + age;

Issues: Hard to read with many variables, easy to forget spaces, creates multiple temporary strings

Interpolation Recommended ✓

string name = "Ahmed";
int age = 25;

string msg = $"Name: {name}, Age: {age}";

Why: Clean syntax, easy to read, compile-time checked, supports format specifiers

↧ Click to reveal

Composite Formatting Legacy

Composite formatting uses numbered placeholders like {0}, {1}. It's common in older code and still appears in libraries.

Examples

string name = "Ahmed";
int age = 25;

string msg1 = string.Format("Name: {0}, Age: {1}", name, age);
Console.WriteLine("Name: {0}, Age: {1}", name, age);

Issues: Index mismatch errors at runtime, hard to read with many arguments, no compile-time checking

When to use: Localization, logging frameworks, legacy code maintenance

switch Statement

Use switch when you have many fixed options. It is often cleaner than many else if blocks.

Example

int day = 3;

switch (day)
{
    case 1:
        Console.WriteLine("Saturday");
        break;
    case 2:
        Console.WriteLine("Sunday");
        break;
    case 3:
        Console.WriteLine("Monday");
        break;
    default:
        Console.WriteLine("Unknown");
        break;
}
Don't forget break in classic switch cases.

switch vs if-else: Performance

switch

✓ Jump Table for dense int/enum

✓ Hash lookup for strings

✓ Order doesn't affect performance

! Only fixed values (no ranges)

if-else

✓ Faster if first condition often true

✓ Supports ranges & complex logic

! Sequential evaluation

! Order matters for performance

How C# Compiler Optimizes switch

Dense int/enum

Jump Table (O(1))

Direct memory jump

String values

Hash + Length check

Then string compare

Sparse values

Binary search / if-else

e.g., 1, 100, 5000

When Compiler Converts switch → if-else

Few cases (≤ 3)
Jump table overhead not worth it
Sparse/non-sequential values
Gaps make jump table inefficient

Recommendation

Use switch: Many fixed values, enums, cleaner code
Use if-else: Ranges, complex conditions, frequent first match

Ternary Operator (?:)

The ternary operator is a compact if/else that returns a value.

condition ? valueIfTrue : valueIfFalse

↑
Check
↑
If true
↑
If false

Ternary vs if-else

✓ Ternary (1 line)

string status = score >= 60 ? "Pass" : "Fail";

✎ if-else (5 lines)

string status;
if (score >= 60)
    status = "Pass";
else
    status = "Fail";

Avoid Nested Ternary

× Hard to read

var result = a > b ? "A" : b > c ? "B" : "C";

✓ Use if-else instead

if (a > b) result = "A";
else if (b > c) result = "B";
else result = "C";

break Statement

break terminates the closest enclosing loop (for, foreach, while, do) or switch statement.

■ break Flow

Loop Running
→
break;
→
Exit Loop ✓

In Loop:

for (int i = 0; i < 10; i++)
{
    if (i == 5)
        break;  // Exit at 5
    Console.Write(i + " ");
}
// Output: 0 1 2 3 4

In Switch:

switch (day)
{
    case "Mon":
        Console.WriteLine("Monday");
        break;  // Required!
    default:
        break;
}

! Note: In nested loops, break only exits the innermost loop.

continue Statement

continue skips the remaining code in the current iteration and starts the next iteration of the closest enclosing loop.

⏭️ continue Flow

Iteration i
→
continue;
→
Iteration i+1 ↩

Skip Even Numbers:

for (int i = 0; i < 6; i++)
{
    if (i % 2 == 0)
        continue;
    Console.Write(i + " ");
}
// Output: 1 3 5

Skip Invalid Data:

foreach (var item in items)
{
    if (item == null)
        continue;

}

goto Statement

goto transfers control to a statement marked by a label. Use sparingly as it can make code hard to follow.

! Warning: goto is generally discouraged. Use break, continue, or methods instead.

✓ Exit Nested Loops:

for (int i = 0; i < 10; i++)
{
    for (int j = 0; j < 10; j++)
    {
        if (found)
            goto Found;
    }
}
return;

Found:
Console.WriteLine("Found!");

✓ In Switch:

switch (choice)
{
    case 1:
        DoSomething();
        break;
    case 2:
        DoExtra();
        goto case 1;
    default:
        goto case 1;
}

◆ Better: Extract nested loops into a method and use return.
